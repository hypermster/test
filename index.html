도면 번호 WEB-001 · 비개발자용

회사 홈페이지는 어떻게 만들어질까요?

홈페이지는 한 채의 건물과 같습니다. 땅 위에 뼈대를 세우고, 인테리어를 하고, 전기를 넣고, 주소판을 답니다. 그림과 비유로 홈페이지의 구조와 만드는 과정을 풀어 봤습니다.

건물로 보는 구조 접속하면 생기는 일 화면과 서버 만드는 과정 GitHub 용어 사전 자주 묻는 질문
1 · 한눈에 보기

홈페이지를 건물 도면으로 그려 보면

도면에서 층을 하나씩 눌러 보세요. 땅(서버) 위에 뼈대(HTML)를 세우고, 인테리어(CSS)와 전기(JavaScript)를 넣고, 꼭대기에 관리실(CMS)을 둡니다.

도면의 층을 누르거나, Tab 키로 이동한 뒤 Enter를 누르세요.

2 · 접속하는 순간

주소를 입력하면 1초 안에 일어나는 일

고객이 휴대폰에서 우리 홈페이지 주소를 입력하면, 화면이 뜨기까지 이런 순서로 일이 진행됩니다.

  1. 01주소 입력고객이 브라우저(크롬, 사파리 등)에 company.com을 입력합니다.
  2. 02위치 찾기DNS라는 인터넷 주소록이 "이 주소의 서버는 어디 있지?"를 찾아 줍니다.
  3. 03서버에 요청찾은 서버(24시간 켜진 컴퓨터)에 "첫 화면을 보내 주세요" 하고 요청합니다.
  4. 04안전하게 전달서버가 글·사진·디자인 파일을 묶어 보냅니다. 자물쇠(HTTPS)로 잠가서 보냅니다.
  5. 05화면 완성브라우저가 받은 파일을 조립해서 고객 화면에 홈페이지를 그립니다.

택배로 치면주소를 적고 → 물류센터가 위치를 찾고 → 창고에 주문하고 → 포장해서 배송하고 → 고객이 상자를 열어 조립하는 과정과 같습니다.

3 · 구성 부품

같은 화면을 세 겹으로 쌓습니다

화면에 보이는 부분(프론트엔드)은 세 가지 언어가 겹겹이 쌓여 만들어집니다. 같은 첫 화면이 단계마다 어떻게 달라지는지 보세요.

보이지 않는 뒤쪽: 서버와 데이터베이스

문의하기처럼 정보를 받아서 처리하고 보관해야 하는 기능은 화면 뒤의 백엔드가 맡습니다. 식당으로 치면 손님이 앉는 홀이 화면이고, 주방이 백엔드입니다.

건물을 받쳐 주는 기반 시설

도메인건물 주소. company.com 같은 이름을 1년 단위로 빌리고 갱신합니다.
호스팅건물이 서 있는 땅. 24시간 켜져 있는 컴퓨터(서버)를 월 단위로 빌립니다.
SSL 인증서현관 자물쇠. 주소창의 자물쇠 표시로, 주고받는 정보를 암호화합니다.
CDN전국 지점. 사진 같은 파일을 고객과 가까운 곳에 복사해 두어 더 빨리 뜨게 합니다.

회사 소개 위주의 홈페이지는 백엔드 없이 화면(프론트엔드)만으로 만들기도 합니다. 문의 양식이나 게시판처럼 정보를 저장해야 할 때 백엔드가 필요합니다.

4 · 진행 순서

홈페이지가 만들어지는 6단계

소개용 회사 홈페이지(10~20쪽 규모)는 보통 3개월 안팎이 걸립니다. 아래 일정표는 일반적인 예시이고, 규모와 기능에 따라 달라집니다.

  1. 기획

    참여: 회사 담당자, 기획자

    누구에게 무엇을 보여 줄지 정하고, 메뉴 구성과 페이지별 내용을 정리합니다.

    결과물 사이트맵, 와이어프레임

  2. 디자인

    참여: 디자이너

    회사 로고와 색상에 맞춰 PC와 모바일 화면 시안을 만들고 회사가 확인합니다.

    결과물 화면 디자인 시안

  3. 개발

    참여: 프론트엔드·백엔드 개발자

    시안을 실제로 작동하는 코드로 옮깁니다. 코드는 GitHub에 매일 저장됩니다.

    결과물 미리보기용 홈페이지

  4. 테스트

    참여: 전원

    여러 휴대폰과 브라우저에서 깨진 곳, 오타, 끊긴 링크, 문의 양식 동작을 점검합니다.

    결과물 수정 목록과 반영 완료

  5. 오픈(배포)

    참여: 개발자

    완성된 파일을 서버에 올리고 도메인을 연결합니다. 이때부터 누구나 접속할 수 있습니다.

    결과물 공개된 홈페이지

  6. 운영·유지보수

    참여: 회사 담당자, 개발자

    소식과 사진을 갱신하고, 보안 업데이트와 오류 수정을 이어 갑니다.

    결과물 늘 최신인 홈페이지
5 · 코드 보관소

GitHub는 왜 쓰나요?

GitHub는 홈페이지 코드를 보관하는 온라인 금고입니다. 여러 사람이 동시에 작업해도 서로 덮어쓰지 않게 해 주고, 모든 수정 내역을 기록으로 남깁니다. 문서의 "버전 기록" 기능을 아주 정교하게 만든 것이라고 생각하면 됩니다.

저장소 Repository
프로젝트 하나의 금고. 홈페이지 코드 전체가 들어 있습니다.
커밋 Commit
저장 버튼을 누른 기록. 누가, 언제, 무엇을 바꿨는지 메모와 함께 남습니다.
브랜치 Branch
원본을 건드리지 않는 연습장. 새 기능을 따로 만들어 보고 괜찮으면 합칩니다.
풀 리퀘스트 PR
"이렇게 바꿔도 될까요?" 하는 검토 요청서. 승인되면 원본에 반영됩니다.
배포 Deploy
승인된 코드를 실제 홈페이지에 올리는 일. 자동으로 설정하면 합치는 즉시 반영됩니다.
되돌리기 Revert
잘못 바꿔도 이전 기록으로 언제든 돌아갈 수 있습니다. 실수가 두렵지 않은 이유입니다.
6 · 용어 사전

회의에서 자주 듣는 말

용어쉬운 뜻
반응형PC, 태블릿, 휴대폰 화면 크기에 맞춰 배치가 자동으로 바뀌는 것
퍼블리싱디자인 시안을 HTML·CSS로 옮겨 실제 화면으로 만드는 작업
와이어프레임색 없이 상자와 선으로 그린 페이지 배치도

7 · 자주 묻는 질문

이럴 땐 어떻게 하나요?

문구 하나 바꾸는데 왜 개발자에게 요청해야 하나요?

관리자 페이지(CMS)가 없는 홈페이지는 글자가 코드 안에 직접 들어 있기 때문입니다. 자주 바뀌는 부분(공지, 채용, 포트폴리오)은 처음 만들 때 관리자 페이지에서 직접 고칠 수 있게 요청하면 좋습니다.

고쳤다는데 제 화면에서는 그대로예요.

브라우저가 예전 파일을 기억(캐시)하고 있을 가능성이 큽니다. 새로고침을 하거나 시크릿 창에서 다시 열어 보세요.

오픈한 뒤에도 매달 비용이 드나요?

네. 도메인은 매년, 호스팅은 매달 비용이 나갑니다. 여기에 오류 수정과 보안 업데이트를 맡길 유지보수 계약이 더해지는 경우가 많습니다. 소개용 홈페이지는 호스팅 비용이 거의 들지 않는 방식도 있습니다.

홈페이지의 주인은 누구인가요?

도메인, 호스팅, GitHub 저장소 계정이 회사 명의로 되어 있는지 꼭 확인하세요. 외주 업체 명의로 되어 있으면 업체를 바꿀 때 홈페이지를 옮기기 어려울 수 있습니다.

홈페이지가 안 열려요. 누구에게 연락해야 하나요?

주소 자체가 안 열리면 도메인이나 호스팅 문제일 수 있으니 관리 업체나 개발 담당자에게 알리세요. 일부 페이지만 이상하면 화면 캡처와 접속한 주소를 함께 보내면 빠르게 처리됩니다.

이 안내서는 일반적인 회사 홈페이지 구조를 기준으로 작성했습니다. 실제 구성은 프로젝트마다 다를 수 있습니다.
