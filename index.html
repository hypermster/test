비개발자를 위한 안내서

회사 홈페이지는 어떻게 만들어질까요?

홈페이지를 하나의 건물이라고 생각하면 쉽습니다. 땅이 있고, 주소가 있고, 뼈대와 인테리어가 있고, 보이지 않는 곳에 관리실이 있죠. 이 페이지는 개발 용어를 몰라도 홈페이지의 구조와 만드는 과정을 이해할 수 있도록 정리했습니다.

건물로 보는 구조 접속하면 생기는 일 앞단과 뒷단 만드는 과정 GitHub의 역할 용어 사전 자주 묻는 질문
1 · 한눈에 보기

홈페이지는 한 채의 건물입니다

아래 층을 하나씩 눌러 보세요. 맨 아래 땅부터 위로 올라가며 쌓입니다.

2 · 접속 순간

주소를 입력하면 1초 안에 일어나는 일

고객이 휴대폰에서 우리 홈페이지 주소를 입력하면, 화면이 뜨기까지 다음 순서로 일이 진행됩니다.

  1. 주소 입력고객이 브라우저(크롬, 사파리 등)에 company.com을 입력합니다.
  2. 주소 찾기DNS라는 인터넷 전화번호부가 "이 주소의 건물은 어디 있지?"를 찾아 줍니다.
  3. 서버에 요청찾은 위치의 컴퓨터(서버)에 "첫 화면 보내 주세요" 하고 요청합니다.
  4. 파일 전달서버가 글, 사진, 디자인 파일을 묶어서 보냅니다. 자물쇠(HTTPS)로 잠가서 안전하게 보냅니다.
  5. 화면 완성브라우저가 받은 파일을 조립해 고객 화면에 홈페이지를 그려 줍니다.

택배에 비유하면: 주소를 적고 → 물류센터가 위치를 찾고 → 창고에 주문하고 → 포장해서 배송하고 → 고객이 상자를 열어 조립하는 과정입니다.

3 · 구성 부품

보이는 앞단, 보이지 않는 뒷단

개발자들은 홈페이지를 크게 두 부분으로 나눠서 말합니다. 식당으로 치면 손님이 앉는 홀과 손님이 보지 못하는 주방입니다.

프론트엔드 손님이 보는 홀 · 화면에 보이는 모든 것

  • HTML: 뼈대제목, 문단, 사진, 버튼이 어디에 있는지 정합니다.
  • CSS: 인테리어색상, 글꼴, 간격, 모바일에서의 배치를 정합니다.
  • JavaScript: 움직임메뉴 열기, 슬라이드 넘기기, 입력값 확인처럼 반응하는 동작을 담당합니다.

백엔드 주방 · 화면 뒤에서 일을 처리하는 곳

  • 서버 프로그램: 요리사문의하기 양식을 받아 담당자에게 메일로 보내는 등 실제 처리를 합니다.
  • 데이터베이스: 창고공지사항, 채용 공고, 문의 내역 같은 정보를 보관합니다.
  • 관리자 페이지(CMS): 주문판개발자 없이도 담당자가 글과 사진을 직접 고칠 수 있는 화면입니다.

건물을 받쳐 주는 기반 시설

도메인건물 주소. company.com 같은 이름을 1년 단위로 빌립니다.
호스팅건물이 서 있는 땅. 24시간 켜져 있는 컴퓨터를 월 단위로 빌립니다.
SSL 인증서현관 자물쇠. 주소창의 자물쇠 표시로, 주고받는 정보를 암호화합니다.
CDN전국 지점. 사진 같은 파일을 가까운 곳에 복사해 두어 더 빨리 뜨게 합니다.

회사 소개 위주의 홈페이지는 백엔드 없이 프론트엔드만으로 만들기도 합니다. 문의 양식이나 게시판처럼 정보를 저장해야 할 때 백엔드가 필요합니다.

4 · 진행 순서

홈페이지가 만들어지는 6단계

기간은 소개용 회사 홈페이지(10~20쪽 규모)를 기준으로 한 일반적인 예시입니다. 규모와 기능에 따라 달라집니다.

  1. 기획

    참여: 회사 담당자, 기획자1~2주

    누구에게 무엇을 보여 줄지 정합니다. 메뉴 구성표(사이트맵)와 페이지별 내용 배치도(와이어프레임)가 결과물입니다.

  2. 디자인

    참여: 디자이너2~3주

    회사 로고와 색상에 맞춰 실제 화면 시안을 만듭니다. PC와 모바일 화면을 각각 디자인하고 회사가 확인합니다.

  3. 개발

    참여: 프론트엔드·백엔드 개발자3~6주

    디자인 시안을 실제로 작동하는 코드로 옮깁니다. 이 단계의 코드는 GitHub에 매일 저장됩니다.

  4. 테스트

    참여: 전원1주

    여러 휴대폰과 브라우저에서 깨지는 곳이 없는지, 오타와 링크 오류가 없는지, 문의 양식이 잘 가는지 확인합니다.

  5. 오픈(배포)

    참여: 개발자하루

    완성된 파일을 호스팅 서버에 올리고 도메인을 연결합니다. 이때부터 누구나 접속할 수 있습니다.

  6. 운영·유지보수

    참여: 회사 담당자, 개발자계속

    소식과 사진을 갱신하고, 보안 업데이트와 오류 수정을 이어 갑니다. 홈페이지는 만든 뒤에도 관리가 필요합니다.

5 · 코드 보관소

GitHub는 왜 쓰나요?

GitHub는 홈페이지 코드를 보관하는 온라인 금고입니다. 여러 사람이 동시에 작업해도 서로 덮어쓰지 않게 해 주고, 모든 수정 내역을 기록으로 남깁니다. 문서의 "버전 기록" 기능을 아주 정교하게 만든 것이라고 생각하면 됩니다.

저장소 (Repository)
프로젝트 하나의 금고. 홈페이지 코드 전체가 여기 들어 있습니다.
커밋 (Commit)
저장 버튼을 누른 기록. 누가, 언제, 무엇을 바꿨는지 메모와 함께 남습니다.
브랜치 (Branch)
원본을 건드리지 않는 연습장. 새 기능을 따로 만들어 보고, 괜찮으면 합칩니다.
풀 리퀘스트 (PR)
"이렇게 바꿔도 될까요?" 하는 검토 요청서. 다른 사람이 확인하고 승인하면 원본에 반영됩니다.
배포 (Deploy)
승인된 코드를 실제 홈페이지에 올리는 일. 자동으로 설정해 두면 승인과 동시에 홈페이지가 바뀝니다.

잘못 바꿔도 이전 기록으로 언제든 되돌릴 수 있습니다. 그래서 GitHub를 쓰면 실수가 두렵지 않습니다.

7 · 자주 묻는 질문

이럴 땐 어떻게 하나요?

문구 하나 바꾸는데 왜 개발자에게 요청해야 하나요?

관리자 페이지(CMS)가 없는 홈페이지는 글자가 코드 안에 직접 들어 있기 때문입니다. 자주 바뀌는 부분(공지, 채용, 포트폴리오)은 처음 만들 때 관리자 페이지에서 직접 고칠 수 있게 요청하면 좋습니다.

고쳤다는데 제 화면에서는 그대로예요.

브라우저가 예전 파일을 기억(캐시)하고 있을 가능성이 큽니다. 새로고침을 하거나, 시크릿 창에서 다시 열어 보세요.

오픈한 뒤에도 매달 비용이 드나요?

네. 도메인은 매년, 호스팅은 매달 비용이 나갑니다. 여기에 오류 수정과 보안 업데이트를 맡길 유지보수 계약이 더해지는 경우가 많습니다. 소개용 홈페이지는 호스팅 비용이 거의 들지 않는 방식도 있습니다.

홈페이지의 주인은 누구인가요?

도메인, 호스팅, GitHub 저장소 계정이 회사 명의로 되어 있는지 꼭 확인하세요. 외주 업체 명의로 되어 있으면 업체를 바꿀 때 홈페이지를 옮기기 어려울 수 있습니다.

홈페이지가 안 열려요. 누구에게 연락해야 하나요?

주소 자체가 안 열리면 도메인이나 호스팅 문제일 수 있으니 관리 업체나 개발 담당자에게 알리세요. 일부 페이지만 이상하면 개발 담당자에게 화면 캡처와 접속한 주소를 함께 보내면 빠르게 처리됩니다.

이 안내서는 일반적인 회사 홈페이지 구조를 기준으로 작성했습니다. 실제 구성은 프로젝트마다 다를 수 있습니다.
